# Willow Decoder Audit — Pre-registration

**Instance:** `willow-decoder-s1`  
**Status:** PRE-REGISTERED  
**Purpose:** Independent reproduction and scope audit of the publicly deposited Willow surface-code decoding artifacts.

---

## 1. Scope

This audit evaluates only claims that can be tested from the publicly deposited
artifacts in the referenced archive.

The audit does **not** attempt to reproduce unpublished training data, proprietary
model weights, unpublished neural-decoder implementations, or claims whose required
artifacts are absent from the deposit.

The audit distinguishes:

1. properties directly recomputable from deposited artifacts;
2. properties whose absence can be established from the deposited artifact;
3. claims that cannot be evaluated because their required evidence is not deposited.

No inference from absence of an artifact to non-existence outside the archive is permitted.

---

## 2. Provenance

Source archive:

`Zenodo 10.5281/zenodo.13273331`

The audit operates on the locally preserved extracted subset and its manifest.

`data_manifest.json`.

A hash mismatch is a **HALT** condition.

## 3. Population Definition

The Libra population is defined operationally, not by a number copied from a
secondary report.

### P1

Let an experimental root be a directory containing a deposited Libra pipeline
at:

`decoding_results/libra_decoder_with_rl_optimized_prior/`

Then:

```text
N_Libra =
count(experimental roots containing
      decoding_results/libra_decoder_with_rl_optimized_prior/)
```

The expected value from the preserved archive listing is:

```text
N_Libra = 364
```

The previously observed value `1092` is **not** interpreted as the population.

It is the number of ZIP entries generated by:

```text
364 × (pipeline directory + error_model.dem + obs_flips_predicted.b8)
= 1092
```

The harness must derive `N_Libra` from the manifest itself.

It must not accept `364` as an externally supplied constant.

If the derived value differs from 364:

```text
HALT: P1 population mismatch
```

No Target A result may be interpreted after this halt.

## 4. Target B — Neural Artifact Scope Finding

### Claim under test

Whether the publicly deposited artifact contains files corresponding to neural
decoder predictions or model-weight artifacts.

### Test

Search the complete preserved manifest/path listing for the relevant artifact
classes.

The test records all matching paths and their count.

Primary indicators include path/name components containing:

```text
neural
weight
```

The search is case-insensitive.

### Decision

```text
count(neural/weight artifacts) == 0
```

produces:

```text
TARGET B: ABSENCE FROM DEPOSITED ARTIFACT
```

This result must **not** be phrased as:

> no neural decoder exists

or:

> no neural decoder was used

It establishes only that such artifacts are absent from the audited public
deposit.

Any non-zero match is recorded verbatim and prevents the zero-artifact finding.

## 5. Target A1 — Libra Logical Error

### Input

The deposited Libra predicted and actual bitstreams.

For each Libra experiment, the harness recomputes the logical-error statistic
from the deposited bitstreams.

No value from the source report is used as an input to the calculation.

### Target

Reported reference value:

```text
epsilon_7 = (1.71 ± 0.03) × 10^-3
```

### Acceptance rule

The recomputed value is compared with the pre-registered target using:

```text
R1 = 0.005 × 10^-3
```

equivalent to half of the second displayed decimal place in units of `10^-3`.

The fit procedure, parameterization, data selection, and rounding rules are fixed
before execution.

No manual adjustment of the fit is permitted after observing the result.

If the recomputed value falls outside the registered tolerance:

```text
HALT: A1 mismatch
```

The result is not repaired by changing the fit, excluding observations, or
changing the tolerance.

## 7. Gates

### G0 — Provenance and Integrity

Required:

* source archive identified;
* preserved manifest available;
* all audited input hashes verified;
* no manifest/input substitution.

Failure:

```text
HALT
```

### G1 — Population

Required:

```text
N_Libra = 364
```

derived from the manifest.

Failure:

```text
HALT
```

### G2 — Target B Scope Finding

Record whether neural/weight artifacts are present.

This gate does not infer anything about artifacts outside the deposit.

### G3 — Reproduction

Run the deterministic reproduction harness.

Required outputs:

```text
results/summary.json
results/manifest.sha256
```

A1 and A2 are evaluated only from the deposited data.

---

## 8. Determinism

The harness must be deterministic.

The same manifest and identical input bitstreams must produce identical
`results/summary.json`.

Any stochastic procedure used by the fitting implementation must either:

1. be eliminated in favour of a deterministic procedure, or
2. have its seed explicitly fixed and recorded.

No parameter may be selected after inspection of the resulting target value.

---

## 9. Failure Handling

The following are protocol failures rather than scientific results:

* missing input artifact;
* SHA-256 mismatch;
* population mismatch;
* malformed bitstream;
* inconsistent experiment structure;
* non-deterministic reproduction;
* missing required manifest information.

A protocol failure produces:

```text
HALT
```

and the affected target is not scored.

A numerical disagreement after a successful protocol run is a **result**, not a
protocol failure.

---

## 10. Reporting Rule

The audit reports four independent outcomes:

```text
P1: population determination
B:  deposited-artifact scope finding
A1: recomputed epsilon_7
A2: recomputed Lambda
```

No single result is permitted to be used as evidence for another.

In particular:

```text
B != proof of absence outside the deposit
A1 != validation of Target B
A2 != validation of Target B
```

---

## 11. Reproduction Order

The audit is executed in the following order:

```text
G0
 ↓
P1
 ↓
G2 / Target B
 ↓
A1
 ↓
A2
```

The manifest is preserved before numerical recomputation.

The population is derived before any target result is interpreted.
